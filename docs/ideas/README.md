# Ideas & backlog

Unscheduled ideas, feature candidates, and problems worth solving that are not yet committed to a roadmap doc or the spec.

**How this differs from its neighbours:**

- `ai-governance-product-spec.md` — decided product shape. Things graduate *into* it.
- `docs/roadmap/` — committed or near-committed pillars with a version attached (v0.2 MCP + telemetry, release automation).
- `docs/ideas/` (here) — not committed, no version, possibly out of scope. Cheap to add, cheap to kill.
- `docs/superpowers/specs/` and `plans/` — design and implementation docs for work actually being built.

**Lifecycle:** an idea gets a file here → if it survives pressure-testing it graduates to a spec section or a roadmap doc → the idea file gets a one-line pointer to where it went, or is deleted. Ideas that are rejected stay here with a `Status: rejected` line and the reason, so we don't relitigate them.

Every file starts with a status line, the spec sections it touches, and an explicit statement of what it would mean for the product boundaries in spec §4.
